🧰 The atelier

Every command is a piece that just fits.

No boilerplate. No copy-paste archaeology. A complete lifecycle for reusable modules — from discovery to teardown.

🔎
brico extract

X-ray your codebase

Point Bricolage at any NestJS or Next.js project and it surfaces the parts worth reusing — auth, mailers, payment flows — ranked by confidence. Your best work, found automatically.

📦
brico capture

Bottle the craftsmanship

One command snapshots a module — files, dependencies, env vars, wiring — into an immutable, semver'd piece with a manifest. Versions are never overwritten. History is forever.

⚡
brico add

Snap. Wired. Done.

Resolves the right version, copies the files, records it in brico.json, merges required env vars into .env.example, and hands you exact framework wiring steps.

🔍
brico list · search

Every piece, findable

Search your entire Vault by name, tag, or description in milliseconds. A self-healing index.json means the catalog is always in sync — even after messy git merges.

🩺
brico doctor

Green means go

One command validates the engine, adapters, Vault, and your project — shown as a row of set-green and loose-red tiles. Trust your setup before every ship.

🎛
brico ui

A cockpit in your terminal

Browse the Vault as a living mosaic of your best work. Live filtering, spec sheets, version history, doctor and extract — all full-screen, all keyboard-driven, all beautiful.

🗑
brico remove

Un-snap cleanly

Modules leave the way they came: files removed, records updated, cleanup steps printed. No orphaned imports, no mystery leftovers, no residue.

Quick start

Build the engine, capture your first module, and snap it into a fresh project.

# 1. Build the engine (single static binary, no runtime required) cd engine && go build -o ../brico ./cmd/brico && cd .. # Use a local demo Vault for this walkthrough export BRICO_VAULT="$PWD/.demo-vault" # 2. See what's reusable in the sample source project ./brico --cwd examples/nest-source extract # 3. Capture the auth module into the Vault ./brico --cwd examples/nest-source capture auth -y \ -d "JWT authentication with Passport & bcrypt" -t security,jwt,auth # 4. Browse the Vault ./brico list ./brico search jwt # 5. Drop it into a fresh project ./brico --cwd examples/nest-target add auth -y # 6. Validate everything ./brico --cwd examples/nest-target doctor

add copies the module's files, records it in brico.json, appends required variables to .env.example, and prints framework-specific wiring steps — like "add AuthModule to the AppModule imports array."

The Vault & the Manifest

A local directory under git. Immutable history, self-healing index, offline-first.

<vault>/ index.json # searchable summary of every module auth/ 0.1.0/ brico.manifest.json # the manifest for this snapshot auth.service.ts # the module's files, exactly as declared ... 0.2.0/ ...
  • ✓Immutable history — publish refuses to overwrite an existing version; changes require a version bump. Every publish is a deterministic git commit.
  • ✓Self-healing index — index.json is rebuilt from disk after every publish, so a hand-edited or merged Vault reconciles automatically.
  • ✓Offline-first — no network required. Git is the seam along which remote and team Vaults arrive later.
  • ✓The manifest is the contract — identity, versions, deps, env vars, exports, compatibility, and lifecycle hooks. Behavior is data, not engine code.

Developing Bricolage

A single Go module. Minimal dependencies — cobra for the CLI; semver lives in-tree.

cd engine go build ./... # compile go test ./... # unit + integration tests go vet ./... # static checks

Adding a framework = one new package implementing the 6-method Adapter interface + one blank import. CI runs format, vet, build, and tests on Linux, macOS, and Windows.

type Adapter interface { ID() string Framework() string DefaultInstallPath(m *manifest.Manifest) string SuggestCaptures(projectRoot string) ([]CaptureSuggestion, error) WireAdd(projectRoot string, m *manifest.Manifest) []WireStep WireRemove(projectRoot string, m *manifest.Manifest) []WireStep }
