For engineering leaders

Every team rebuilds the same things. Then their AI rebuilds them again.

The auth module your team perfected two projects ago still exists — buried in that repo, tangled with its dependencies, invisible to search. So the next project writes a new one, and an assistant asked the same question writes a third.

Knowledge nobody can find

It is in a repo, in a head, or in a pull request from 2023 — never in one searchable place.

AI that regenerates

An assistant with no memory of what you own writes a fresh version every time it is asked.

Why it matters now

Generation is cheap; review is not. Every regenerated module is another one to maintain.

Today, without BWX regenerated ×4

"We need JWT auth in the new service."

Someone remembers "we did this before" but not where.

The assistant scans the whole codebase for context.

It writes a fresh implementation that must be reviewed line by line.

You now maintain a fourth, slightly different auth module.

Cost: tens of thousands of tokens, a review cycle, new bugs
With BWX reused

For engineers

Capture once. Find it anywhere. Add it in one command.

Three verbs, one binary. Everything lives in a git folder on your machine called the Vault — no server, no account.

Capture

Point BWX at a folder that works. It reads the code, writes the summaries, and versions the result into the Vault as a piece.

vault/pieces/auth/0.1.0/

$ brico capture ./src/auth --name auth
read 6 files · 412 lines
wrote card, surface, summary
saved auth@0.1.0 to the Vault

Find

Search by meaning, not by filename. The same index answers a human at the terminal and an assistant over MCP.

$ brico search "token auth for nest"
auth@0.2.0 jwt, passport, nest
proven in 3 projects · updated 4 mo ago
session@0.3.1 redis-backed sessions
search_pieces("token auth for nest")
→ auth@0.2.0 jwt, passport, nest
proven in 3 projects · updated 4 mo ago
→ session@0.3.1 redis-backed sessions

Add

One command copies the piece into the project, wires what it can, and prints the steps only you can decide.

No install step. No registry.

$ brico add auth

wired .env.example

For AI assistants

Your assistant gets a librarian instead of the whole library.

brico mcp exposes the Vault over the Model Context Protocol. Claude, Cursor, IDE agents, internal copilots — any MCP-capable assistant can search your pieces and recommend reuse before writing anything new.

search_pieces(query, kind?)

Meaning-based search across the Vault.

get_piece(name, level)

Card, surface, summary or source — the caller picks.

plan_reuse(task)

What to reuse for a task, and what is genuinely new.

get_relations(name, kind?)

What this piece depends on, and what depends on it.
