THE PROBLEM

Every team rebuilds the same things. Then their AI rebuilds them again.

The auth module your team perfected two projects ago still exists — buried in that repo, tangled with its dependencies, invisible to search. So the next project writes a new one, and an assistant asked the same question writes a third.

TODAY, WITHOUT BWX — regenerated ×4

"We need JWT auth in the new service."

Someone remembers "we did this before" but not where.

The assistant scans the whole codebase for context.

It writes a fresh implementation that must be reviewed line by line.

You now maintain a fourth, slightly different auth module.

cost: tens of thousands of tokens, a review cycle, new bugs
WITH BWX — reused

"Do we have JWT auth?"

The assistant asks the Vault, not the codebase.

The Vault answers with a card: auth@0.2.0, nest, jwt, proven in 3 projects.

brico add auth copies the piece and prints the two wiring steps.

Nothing new was written. Nothing new needs review.

cost: about 300 tokens and one command

Knowledge nobody can find

Engineering teams lose their best work because it gets buried in old repos, stripped of the context explaining why it was built.

AI that regenerates

AI assistants default to generating new code from scratch, which increases your maintenance burden and introduces subtle bugs.

Why this matters now

With AI making code generation free, the new bottleneck is review and maintenance; reusing proven pieces is the only way to scale.

HOW IT WORKS

Capture once. Find it anywhere. Add it in one command.

Three verbs, one binary. Everything lives in a git folder on your machine called the Vault — no server, no account.

1

Capture

Save the piece to your Vault. The CLI extracts the files, asks you for context, and generates the summaries.

HUMAN
$ brico capture
Select files: [src/auth/*]
Captured auth@0.1.0
2

Find

Search by name, capability, or meaning. The local SQLite index finds it instantly.

HUMAN / AI ASSISTANT
$ brico search "auth"
auth@0.2.0 (proven)
3

Add

Copy the files into your working directory and get the exact wiring steps.

HUMAN
$ brico add auth
Copied to src/auth/
Done.

Card ~50

"Do we have something for X?"

Name, tags, capabilities, and dependencies. Enough to match a search query.

Surface ~200–400

"How do I call it?"

The API signature, exported types, and wiring instructions.

Summary ~500

"Why was it built this way?"

The human-written or AI-generated explanation of architectural choices.

Full source

"I need to change it."

The actual code files. Read only when a modification is necessary.

Whoever is asking — human or AI — climbs only as high as the task needs.
